# Vega-Lite patterns for `vega-paper`

Hand-written Vega-Lite specs and the **`render`** workflow. See [SKILL.md](../SKILL.md) for CLI commands. Prefer **`infer`** for CSV/JSON → spec unless a case below applies.

## When to use `render`

Use **`render`** (not `infer`) when:

| Situation | Why |
|-----------|-----|
| User already has a `.vl.json` spec | No data file to infer from |
| Spec was edited after a prior `infer` run | Preserve custom JSON changes |
| Chart needs marks or encodings **`infer` does not support** | e.g. custom layer, non-standard mark options |
| Example or template from docs/repo | Start from committed specs under `examples/` |

Stay on **`infer`** when starting from tabular data and one of the six supported `--chart` types fits. See [Chart selection](chart-selection.md).

## Spec minimum requirements

Hand-written specs should be valid **Vega-Lite** JSON the CLI can read and lint.

| Requirement | Notes |
|-------------|-------|
| **`$schema`** | Use a Vega-Lite v6 schema URL (see repo examples) |
| **`mark` + `encoding`** (or composed `layer` / `facet` / `concat`) | Must be recognizable as Vega-Lite |
| **Explicit `width` and `height`** | Recommended for paper figures; `size-missing` warns if absent — see [Paper style guide](paper-style-guide.md) |
| **Axis titles** on x/y quantitative/nominal channels | Avoid `axis-title-missing` warnings |
| **Data** | Inline `data.values`, external file via `data.url`, or top-level data inherited in layers |

**`render`** output formats are **SVG**, **PNG**, and **PDF** (`--format` on `render`/`infer`). Themes apply at render time via `--theme`; they do not replace lint or sizing on the spec itself.

## Render flags

Required and common flags for **`render <spec>`**:

| Flag | Role |
|------|------|
| **`--out <path>`** | Required. Writes rendered output; sibling `*.meta.json` is created next to the output basename |
| **`--format svg|png|pdf`** | Output format (default inferred from extension when omitted) |
| **`--theme <name>`** | Strongly recommended for publication; applies VegaPaper theme config — see [Theme catalog](theme-catalog.md) |

Command examples: [SKILL.md](../SKILL.md) Secondary workflow.

## Lint for hand-written specs

Run **`lint`** on the spec path with an appropriate **`--lint-profile`** before final render.

- Fix issues by **editing the JSON** (or regenerating via `infer` if you switch back to tabular data).
- Infer flags (`--title`, `--width`, `--chart`, …) do **not** apply to bare `render`.
- Rule ids, profiles, and sizes: [Paper style guide](paper-style-guide.md).

Optional **`--strict`** gates warnings the same as on `infer`.

## Snippet patterns

Minimal Vega-Lite shapes for hand-written specs. Adapt field names, sizes, and titles. Full example: [basic-line/chart.vl.json](../../../examples/basic-line/chart.vl.json).

### Line with series color

Single unit spec with inline or external data:

```json
{
  "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
  "width": 360,
  "height": 220,
  "data": { "values": [] },
  "mark": { "type": "line", "point": true },
  "encoding": {
    "x": { "field": "epoch", "type": "quantitative", "title": "Epoch" },
    "y": { "field": "metric", "type": "quantitative", "title": "Score" },
    "color": { "field": "model", "type": "nominal", "title": "Model" }
  }
}
```

### Faceted small multiples

Top-level `facet` + inner `spec` (see [faceted-training/chart.vl.json](../../../examples/faceted-training/chart.vl.json)):

```json
{
  "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
  "data": { "url": "data.csv" },
  "facet": { "field": "split", "type": "nominal" },
  "spec": {
    "width": 360,
    "height": 240,
    "mark": "line",
    "encoding": {
      "x": { "field": "epoch", "type": "quantitative", "title": "Epoch" },
      "y": { "field": "f1", "type": "quantitative", "title": "F1" },
      "color": { "field": "model", "type": "nominal", "title": "Model" }
    }
  }
}
```

### Layered marks

Combine marks in one view when `infer` cannot express the design (custom point + line styling, rules, etc.):

```json
{
  "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
  "width": 360,
  "height": 220,
  "data": { "url": "data.csv" },
  "layer": [
    { "mark": "line", "encoding": { "x": { "field": "x", "type": "quantitative" }, "y": { "field": "y", "type": "quantitative" } } },
    { "mark": "point", "encoding": { "x": { "field": "x", "type": "quantitative" }, "y": { "field": "y", "type": "quantitative" } } }
  ]
}
```

After editing snippets, run **`lint`** then **`render`**. Prefer **`infer`** when the chart matches a supported `--chart` type.

## Common mistakes

| Mistake | Why it fails / looks wrong | Fix |
|---------|---------------------------|-----|
| Running **`infer`** when user supplied a finished spec | Overwrites or duplicates work | `lint` then `render` the existing file |
| Running **`render`** without lint on a new hand-written spec | Size/axis warnings reach the paper | `lint --lint-profile paper` first; fix spec |
| Expecting **`infer` block in meta** after `render` | Render meta has `"command": "render"` only (input, output, theme, versions) | Use `infer` meta when provenance needs chart/x/y snapshot |
| Hand-writing JSON when **`infer` supports the chart** | Harder to keep consistent with CLI validation | Use primary `infer` workflow from SKILL |
| Omitting **`--theme`** on render | Spec renders without VegaPaper styling | Pass e.g. `paper-clean` — see theme catalog |
